# GarbageGo 工作計畫（4 週、4 人）— 從這裡開始

> **狀態：** Approved（架構師 2026-11-22 確認）
> **用途：** 組員只要先看這一頁。細節在最下面的「文件地圖」。

## 一句話

**做一個 App：你給位置，它告訴你「去哪個收運點倒垃圾來得及」。**

## 5 個重點

1. **後端**：Python + 資料庫，放在一位組員不關機的電腦上，用 Cloudflare 開一個 `https` 網址給 App 連。
2. **資料**：臺中市的收運點（約 2 萬個）+ 垃圾車 GPS。收運點的座標已經算好 **95.6%**。
3. **推薦規則**：車最早幾點到 −（現在 + 走過去要多久）− 3 分鐘緩衝。**大於等於 0 就來得及。**
4. **不能亂講**：時間和距離都由程式算，LLM 不能自己編。GPS 太舊、只有表定時間，都要明講。
5. **v1 只推薦一般垃圾**。資源回收時段只顯示。

## 誰負責什麼

| 角色 | 姓名 | 負責 |
|---|---|---|
| 前端 | （填） | Android App：地圖、畫面 |
| 架構師 | （填） | 後端骨架、API 規格、推薦邏輯、對話（LLM）、整合與文件 |
| 後端 A | （填） | 資料表、匯入資料、找附近收運點、步行時間、部署主機 |

## 4 週時程

| 週 | 做完要看得到 |
|---|---|
| **1 地基** | 後端跑得起來；App 接得到假資料；收運點和舊 GPS 都進資料庫；確認 `d1`～`d7` 是星期幾 |
| **2 能推薦** | App 給位置 → 看到附近收運點、步行時間、推薦和備案（先用表定時間） |
| **3 即時 + 對話** | 推薦改用即時 GPS，顯示資料時間；可以用聊天的方式問 |
| **4 Demo** | ETA 評估（只寫真的跑出來的數字）、Demo 備援資料、彩排 |

**每週五**：大家把分支合進 `main`，從 App 到資料庫整條跑一次。

## 第 1 週：每個人的主要工作

| 誰 | 做什麼 | 注意 |
|---|---|---|
| 架構師 | 後端骨架 + 假資料 API | **其他人都在等這個，最先做** |
| 前端 | App 骨架、地圖底圖、接假資料；設定頁可以改後端網址 | Tunnel 網址會變，所以要能改 |
| 後端 A | 建資料表、匯入收運點和座標、架好部署主機 | — |
| 後端 B | **第一天**把 GPS 收集程式搬到部署主機；匯入舊 GPS；確認 `d1`～`d7` | 晚一天搬，就少一天資料 |

## 已經決定的事

| 決定 | 為什麼 |
|---|---|
| App：Android（Jetpack Compose）+ MapLibre 地圖 + 國土測繪中心底圖 | 免費、不用 Google 金鑰 |
| 步行路線：Valhalla 公開伺服器；失敗就改用直線距離粗估 | 免費；掛了也不會整個壞掉 |
| LLM：Claude API | 架構師決定 |
| 後端：Python + FastAPI + PostgreSQL/PostGIS | 照原本規劃 |
| 主機：組員電腦 + Cloudflare Tunnel | 免費，不用租雲端 |
| v1 鎖定一份 84004 資料，不中途換版本 | 收運點編號是「排第幾筆」，換版本會錯位 |
| 舊 GPS 的「抓到的時間」要讀原始紀錄，不能用估的 | 重播過去和評估 ETA 都靠這個時間 |
| **國定假日不推薦**，改成提示「請查官方定點班表」 | 假日停止沿街收運，假日班表不在 84004 裡，4 週做不完 |

## 時間不夠時，先砍這些

1. 聊天對話（App 改用按鈕）
2. 進階 ETA（保留表定時間）
3. Valhalla 步行路線（改直線粗估）

**不能砍：** 附近收運點、推薦、資料時間與風險標示。

## 最大的 3 個風險

| 風險 | 怎麼辦 |
|---|---|
| 部署主機重開機或斷網，GPS 和 Demo 一起停 | 開機自動啟動、關閉睡眠、每天看 `/health`、每週備份；Demo 準備歷史資料備援 |
| Tunnel 網址重開就變 | App 設定頁可以改網址 |
| `d1`～`d7` 對應錯，推薦的日子就錯 | 第 1 週後端 B 用 GPS 確認；它排在後端 B 工作的最後，慢了週五回報 |
