# 1. Abstract

> **狀態：** Proposal 草稿；下列系統與評估方法皆為規劃，非已完成的實驗結果。

**A. Attention Getter — Motivation：** 臺中市在 2026 年春節採定時定點收運時，公告各站停留約 5 至 30 分鐘 [I4]。居民需要在有限時間內決定前往哪個收運點；即使能查到垃圾車位置或表定時間，也仍須考慮自己走到現場需要多久。

**B. But — Challenge：** 本組檢視的服務與研究中，尚未找到同時結合垃圾車到點時間、居民步行時間與資料不確定性，直接比較候選收運點是否可行的完整方案。政府開放資料的更新頻率、站點座標與車輛關聯也有待處理的限制 [I9][I10]。

**C. Cure — Proposed Solution：** 本專題提出 GarbageGo，一個以臺中市垃圾清運為情境的 Domain AI Agent，目標是依使用者需求推薦可能趕上的收運點，並在必要時提供備案。

**D. Development — Method：** 系統規劃整合官方車輛動態與收運點資料、步行路網及清運規則，由 GIS Engine 估計步行時間、ETA Engine 估計垃圾車到點時間，並由 Recommendation Engine 依時間餘裕、資料品質與風險評估候選點。LLM Agent 負責理解需求、協調工具及解釋結果；資料不足時標示限制，排程資訊不視為實際到達時間。

**E. Experiments — Evaluation：** 預計使用可取得的臺中資料及經確認的到點觀測，評估排程、距離／速度與歷史統計等可行的 ETA 基準，以 MAE、RMSE 比較誤差，並比較最近點與時間可行性策略的趕上率及誤判率。實際到點時間的取得方式與資料適用性仍須驗證。

**F. Findings — Expected Outcomes：** 預期產生具備依據、資料時間與風險說明的收運點建議，並釐清低頻開放資料對到點估計及居民決策的限制。目前尚未完成系統與比較實驗，不宣稱預測準確度或推薦成效。
