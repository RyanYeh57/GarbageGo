## 1. 用了什麼資料

| 資料 | 來源 | 版本 / 下載時間 |
|---|---|---|
| 收運點 84004 | <https://data.gov.tw/dataset/84004>（JSON，20,090 筆） | 2026-11-16 下載 |
| 臺中市 GIS 門牌點位 | <https://data.gov.tw/dataset/169806> 目錄中的「臺中市115年1月GIS門牌號碼」（Google Drive，CSV，約 157 MB，1,316,674 筆） | 2026-11-16 下載 |

門牌月檔實際欄位（13 欄）：`省市縣市代碼, 鄉鎮市區代碼, 村里, 鄰, 街、路段, 地區, 巷, 弄, 號, TWD97橫坐標, TWD97縱坐標, WGS84經度, WGS84緯度`。數字是全形；`號` 可能帶樓層（例如 `５號三樓之１`）；沒有街路名時改填 `地區`（例如 `十甲巷`）。

資料放在本機暫存目錄，**未進 Git**（檔案太大，且是可重新下載的公開資料）。腳本在 `scripts/geocode/`：

| 檔案 | 用途 |
|---|---|
| `scripts/geocode/match.py` | 比對主程式：`python -I -X utf8 scripts/geocode/match.py <門牌csv> <84004 json> <輸出資料夾>`。`all.csv` 第一欄是 `source_index`（該筆在 84004 陣列的位置，從 0 起） |
| `scripts/geocode/village_check.py` | 里別一致性檢查，並輸出可疑座標清單：`python -I -X utf8 scripts/geocode/village_check.py <門牌csv> <輸出資料夾>/all.csv <輸出資料夾>/suspects.csv`（欄位 `source_index,distance_m`，>3 km） |
| `scripts/geocode/test_match.py` | 正規化與地址解析的單元測試（只用標準函式庫）：`python -I -X utf8 scripts/geocode/test_match.py` |

## 2. 比對方法

1. 兩邊用同一套正規化：全形轉半形、中文數字轉阿拉伯數字（`二段`→`2段`、`一街`→`1街`）、`臺`→`台`、`壳`→`殼`、`-`→`之`。
2. 門牌組成完整字串：`街、路段 + 地區 + 巷 + 弄 + 號`（去掉 `號` 後面的樓層）。
3. 84004 地址去掉括號備註；開頭若是該筆自己的里名（例如 `福山里沙田路…`）就去掉；`15號之3` 改成 `15之3號`；`號` 後面剩下的字（`前`、`旁` 等）記下來後去掉。
4. 行政區代碼不寫死：用里名重疊自動對出 29 區。
5. 依序嘗試：
   - `exact`：行政區＋完整地址一模一樣。
   - `approx_suffix`：去掉「號前」「號旁」等後綴才對到。
   - `approx_base_number`：`263之1號` 對不到，改用 `263號`。
   - `approx_nearby_number`：同一條路/巷，用同側（單雙號相同）最近、差距 ≤10 的門牌。
6. 都對不到 → 不給座標，**不猜**。

## 4. 合理性檢查

- **里別一致率：** 有座標的點中，85.9% 的門牌里別和 84004 的 `village` 相同。
- 不一致的 2,706 筆，離 84004 所寫里別的中心點：<500 m 1,038 筆、500 m–1 km 1,041 筆、1–3 km 493 筆、**>3 km 81 筆**；另 53 筆的里名在門牌資料裡找不到（可能是里鄰調整）。
- 解讀（推論，未驗證）：多數不一致距離很近，可能是 84004 的 `village` 記的是路線所屬里，不是門牌所在里。**>3 km 的 81 筆最可能是錯配，要人工看。**
- 抽 5 筆看座標，都落在臺中市合理範圍內（例如 北屯區 中清路二段9號 → 120.6711, 24.1741）。**還沒有和實際地圖逐筆核對。**

## 6. 限制

- 門牌資料是 115 年 1 月版，84004 的資料時間不明。

## 9. TGOS 批次比對（2026-11-25，Implemented / Unverified）

TGOS 批次地址比對服務 2026-11-25 審核通過。程式：`backend/app/modules/ingestion/tgos.py`（從 `backend/` 執行）。

| 步驟 | 指令 | 說明 |
|---|---|---|
| 1. 做上傳檔 | `python -m app.modules.ingestion.tgos export --geocode <all.csv> --out Address_874.csv` | 格式照 TGOS 範例檔（UTF-8 BOM，`id,Address,Response_Address,Response_X,Response_Y`）。`id` = `source_index`；`Address` = `臺中市` + 區 + 地址（去掉括號備註）。實跑輸出 874 筆 |
| 2. 上傳 TGOS | 人工 | 設定：允許模糊比對、鎖定縣市與鄉鎮市區、忽略村里。回傳座標是 **TWD97 TM2（EPSG:3826）**，一格可能有多個答案，用 `;` 隔開 |
| 3. 匯入結果 | `python -m app.modules.ingestion.tgos import --result <結果.csv>` | 只補 `geom` 是空的點，標 `geocode_source = geocode_level = 'tgos'`；**不會蓋掉本地或人工座標** |

匯入規則：`id` 不存在、或 `Address` 和資料庫算出來的不一樣 → 整批不寫。座標不是 TWD97 → 整批不寫。沒座標 → `unmatched`。多個答案彼此相距 >50 m → `ambiguous`，不寫；≤50 m → 取平均。用 PostGIS `ST_Transform` 轉成 WGS84 後，落在臺中範圍外（經度 120.4–121.5、緯度 23.9–24.5）→ `out_of_area`，不寫。結果檔可讀 UTF-8 或 Big5。

**第 1 次結果（2026-11-26，本機資料庫實跑）：**

| 項目 | 筆數 |
|---|---|
| 送出 | 874 |
| 匯入（`updated`） | **217**（只有 1 個答案 180；2 個答案且相距 ≤50 m 37） |
| 2 個答案相距 >50 m（`ambiguous`） | 150 |
| 找不到（`unmatched`，TGOS 回「找不到指定的門牌地址。」） | 507 |
| 範圍外 | 0 |

匯入後資料庫有座標的點：19,216 → **19,433**（共 20,090）。217 筆座標都在經度 120.51–121.26、緯度 24.02–24.40。

**第 2 次（2026-11-27，本機資料庫實跑）：** 送第 1 次沒找到的 507 筆 + `ambiguous` 150 筆，扣掉「往廠」19 筆（不是民眾倒垃圾的點），共 638 筆。設定改成**不鎖區**、勾「忽略鄉」。

| 項目 | 筆數 |
|---|---|
| 找不到 | 241 |
| 答案彼此相距 >50 m（有的一次回 10 個） | 211 |
| 答案集中（≤50 m） | 186 |
| 回傳地址換到別區 | 0 |

第 2 次的模糊比對比較鬆，答案常常差很多號或換了巷。所以匯入前先用 `scripts/geocode/tgos_filter.py` 篩：**每個答案都要在同一條路／巷，門牌差 ≤10 號**（和本地 `approx_nearby_number` 同標準），不合格的清掉座標。

```
python -I -X utf8 scripts/geocode/tgos_filter.py <TGOS結果.csv> <篩過.csv>
```

篩完留 49 筆（逐筆看過，都是同路、號碼相近）。匯入結果：`updated=46`、`ambiguous=3`（一次回 6–10 個 `之N號`，彼此相距 >50 m）。有座標的點：19,433 → **19,479**（`tgos` 共 263 筆）。

**剩下沒座標：611 筆**（含往廠 19 筆）。不擋 Demo：搜尋本來就排除沒座標的點。

限制：
- TGOS 模糊比對會改地址，回傳地址**沒有一筆和送出的完全相同**。抽樣看到改對的（`崇德十路527號` → `崇德十路一段527號`），也有改錯的（`廍子路33巷6號` → `廍子路700巷33號`、`文心路二段` → `文心路四段`）。`tgos` 等級應視為近似位置，還沒人工核對。**第 1 次的 217 筆沒有經過 `tgos_filter.py`**。拿第 1 次結果試跑篩選，874 筆只留 8 筆：第 1 次的答案多半是 TGOS 幫忙補路段（例如補上「一段」），路名字串不同就被篩掉。所以篩選標準不適合直接套用到第 1 次，要改成人工抽查。
- 第 1 次沒找到的，曾推測是鎖區造成；第 2 次不鎖區後，回傳的答案仍然都在原本的區，所以這個推測**不成立**。
- `geocode_level = 'tgos'` 還沒加進 API 的 `GeocodeLevel`（`docs/api-reference` 分支的 `api-reference.md` 待定事項 2）。
